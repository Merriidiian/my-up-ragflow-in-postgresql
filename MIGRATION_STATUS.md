# PostgreSQL-порт RAGFlow: проверенный срез и оставшаяся работа

Дата среза: **21.10.2026**. Основа — **RAGFlow v1.0.0-rc2**, upstream commit `ac29b4b29928ca65d3efca19b6cfae3f86069b81`. Это сохранение текущей миграции в `main` нового репозитория `Merriidiian/my-up-ragflow-in-postgresql`. История состоит из исходного среза core RC2 и следующего коммита PG-порта. Более новые изменения upstream/main в этот проверенный срез не подмешивались.

**Статус: исходники PG18.6/pg3 подготовлены и прошли компонентные проверки. Полный функциональный аудит и готовность к эксплуатации не заявлены.** Действующий стенд при подготовке этого среза не перезапускался и не переключался.

## Что сохранено

- PostgreSQL непосредственно в исходниках: драйвер, SQL-совместимость, advisory locks, встроенный каталог схемы, транзакционные миграции pg1 → pg2 → pg3. Build не применяет внешний patch и не читает вторую копию исходников.
- Metadata runtime использует только PostgreSQL; MySQL/OceanBase отклоняются как metadata backend. Штатные документные коннекторы/SQL-tools не удалены.
- Офлайн-импорт совместимой Go-схемы RC2 MySQL → пустая PG: read-only snapshot источника, ID/JSON/история/цитаты, row-count/SHA256, sequences и rollback при ошибке. Исходники и тесты импорта сохранены.
- Выбранные зависимости: PostgreSQL 18.6, Infinity 0.7.4, S3 `minio`/pgsty/silo, Kvrocks 2.16.0, NATS JetStream 2.14.2. Лимит документа — **209715200 байт (200 МиБ)**.
- Закреплённые build/runtime references, native package checksums, лицензия upstream. Сборки/веса/рабочие реквизиты и PEM-файлы в публикацию не входят. Ключи для запуска из исходников подготавливаются вне Git; runtime smoke проверял ресурсы закреплённого базового образа.

Исходный каталог компонента в VSM AI назывался `rag-flow-core/`; здесь его содержимое находится **в корне репозитория**. Поэтому пути `rag-flow-core/...` в исторических JSON-манифестах означают происхождение, а не вторую копию движка. Остальные компоненты VSM AI сюда не экспортировались.

## Почему не работает русский OCR

В закреплённом runtime `ocr.res` имеет SHA256 `28b2362ad4ab2dc38769aa72feb535e3a9ddb3fd2a7585a05920e6393b1dc7f7`: **6623 токена**, с blank/space — **6625 CTC-классов**, как в текущем `recVocab`.

В нём присутствуют лишь отдельные кириллические символы, но отсутствуют **«Н», «е», «в», «а»**. Поэтому контрольное **«Нева-31»** не может быть выдано текущим декодером независимо от чёткости скана. Прежний настоящий scan PDF завершил обработку и дал чанк, но потерял русский факт. Латинский контрольный код не является проверкой русского OCR.

Просто дописать буквы в словарь нельзя: индекс выхода модели соответствует определённому символу. Несогласованная подмена словаря меняет смысл выходов и портит распознавание. Нужны совместимые веса и словарь, а при другой геометрии/размерности/именах тензоров — явная адаптация backend с регрессией. Проверка алфавита — необходимое условие, а не доказательство качества OCR.

Добавлен воспроизводимый диагностический инструмент:

```sh
python3 scripts/check_ocr_vocabulary.py /prepared/ocr.res --text Нева-31
python3 scripts/test_ocr_vocabulary.py
```

[Результат проверки словаря](goal/reports/rag-flow-core/checks/ocr-alphabet.json), [точный контракт recognizer и дальнейшие проверки](goal/reports/rag-flow-core/checks/ocr-investigation.md). При сохранении среза модели не скачивались и рабочий runtime не переключался.

## Границы миграции базы

`DB_TYPE=postgres` выбирает backend, но не доказывает корректность существующей базы. PG schema-version и каталог проверяются независимо от исторического `mysql_migration.database.version`. Последний может сохраняться при импорте и читаться дополнительной защитой от downgrade версии приложения, но не разрешает неизвестную PG-схему и не запускает MySQL-цепочку. Это отдельно проверено `TestPostgresLegacyMigrationMarkerIsIndependent`.

Импортёр поддерживает **совместимую Go-схему выбранного RC2 → пустую PG**, а не произвольный старый Python/MySQL dump. Старый источник сначала приводят к нужной upstream-схеме на копии; затем сохраняют согласованную точку остальных хранилищ. Неизвестная пользовательская MySQL-база в этом срезе не проверялась.
