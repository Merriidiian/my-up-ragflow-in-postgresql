# Русский OCR: причина и границы проверки

21.10.2026. Новая проверка — чтение `ocr.res` из закреплённого локального runtime-образа в отдельном контейнере без сети (256 МиБ, без mount рабочего стенда). [Результат](ocr-alphabet.json).

SHA256 словаря `28b2362ad4ab2dc38769aa72feb535e3a9ddb3fd2a7585a05920e6393b1dc7f7` совпадает с ожидаемым upstream `native_integration_test.go`. 6623 строки + blank/space = 6625 CTC-классов; это соответствует `recVocab=6625` в `internal/deepdoc/native/ocr_rec.go`. В словаре есть 6 кириллических символов, но нет «Н», «е», «в», «а». Следовательно, контрольное «Нева-31» этим декодером не представимо независимо от качества входного скана. Upstream-комментарий также явно исключает Cyrillic из golden-кейсов. Это точная причина ограничения текущей пары recognizer/словарь, а не доказательство отсутствия любых других OCR-дефектов.

Унаследованное реальное сканирование (`.local/reports/ragflow-formats.json`): scan PDF обработан, получен чанк, потерян русский факт; полный файл SHA256 `38b3d29ce0ca73063bfc45e6b7e35cce5645ecb75e55a2b87722ab2e4083e418`. Повтор скана → ingestion/retrieval в новом core **не выполнялся**: полного отдельного стека с подготовленным OCR нет, действующий не изменяется.

Добавлен воспроизводимый `scripts/check_ocr_vocabulary.py`, unit-проверки различают латинский контроль и необходимое покрытие русского алфавита. Даже положительный результат проверки словаря не означает качественного OCR.

Требование инфраструктуре: подготовить офлайн совместимые recognition weights + dictionary с русским алфавитом и проверенными checksum/license точных артефактов. Текущий native-контракт: CTC, вход `x`, `[N,3,48,W]`, BGR/нормализация `(pixel/255-0.5)/0.5`, выход `softmax_11.tmp_0`, `[N,T,6625]`, `rec.ort`. Другая размерность/геометрия/имена требуют явной адаптации и тестов core; подмена одного словаря недопустима. Альтернативный локальный OCR backend возможен только с подготовленным runtime/ресурсами, совместимым существующим parser API и отдельной проверкой — здесь он не выбирался и не включался.

Приёмка после подготовки: тот же синтетический русский scan PDF без текстового слоя → ожидаемые кириллические факты в чанках → retrieval по русскому вопросу → ответ с цитатой на верный документ/чанк; также отрицательные входы, латиница, поворот/качество, текстовый PDF/DOCX/XLSX без регрессии. Нужны замеры RAM/CPU и времени на локальном профиле. Сеть наружу не открывать, OCR не снимать из объёма.
